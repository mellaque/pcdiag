# pcdiag

Диагностика Windows-ПК для работы по заявкам техподдержки. Одна команда собирает
короткую сводку «что подозрительно и почему» и подробный отчёт в JSON.

- **Только чтение.** Инструмент ничего не меняет в системе: не пишет в реестр,
  не останавливает службы, не удаляет файлы. Пишет только папку с отчётом.
- **Без установки.** Папка копируется на флешку или в общую папку и запускается оттуда.
- **Для удалённой работы.** Сводка сразу попадает в буфер обмена, а через AnyDesk —
  на компьютер того, кто подключился. Её можно вставить в заметку к заявке.

[![CI](https://github.com/mellaque/pcdiag/actions/workflows/ci.yml/badge.svg)](https://github.com/mellaque/pcdiag/actions/workflows/ci.yml)

## Запуск

Требования: Windows 10 или 11, Windows PowerShell 5.1 (встроена в систему), права администратора.

1. Скопируйте папку на ПК или откройте её из общей папки.
2. Правый клик по `Run.cmd` → «Запуск от имени администратора».

Только некоторые проверки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Invoke-PcDiag.ps1 -Only Uptime,FreeSpace
```

Отчёт сохраняется в `reports\pcdiag_<ИМЯ-ПК>_<дата>` рядом со скриптом,
а если туда нельзя писать — в `%TEMP%`:

| Файл | Что внутри |
|---|---|
| `summary.txt` | Сводка для заметки к заявке |
| `result.json` | Все проверки: статус, пояснения, собранные данные, время выполнения |

Пример сводки (данные выдуманы):

```
Диагностика PC-01, 25.11.2026 14:03 (pcdiag 0.1.0)
Итог: проблем: 1, в норме: 1

[FAIL] Свободное место: мало места: C: 2,1 из 119 ГБ
       - C: системный диск, меньше 3 ГБ: возможны зависания, сбои обновлений и профилей
[ OK ] Аптайм и ОС: Windows 10 Pro, сборка 19045; без перезагрузки 2 дн. 3 ч (с 23.11.2026 09:00)
```

Статусы: `FAIL` — проблема, `WARN` — подозрительно, `ERR` — проверка не смогла
собрать данные, `SKIP` — на этом ПК проверять нечего (например, нет батареи), `OK` — норма.

## Проверки

| Id | Что смотрит | Когда тревожится |
|---|---|---|
| `Uptime` | Версия Windows, время загрузки, быстрый запуск | Больше 14 дней без перезагрузки |
| `DiskHealth` | Состояние внутренних дисков (оценка Windows, износ SSD, температура, неисправленные ошибки), ошибки дисков и NTFS в журнале за 30 дней | Повреждённые блоки, повреждение NTFS, износ от 95 %, Unhealthy (FAIL); повторы и сбросы ввода-вывода, износ от 80 %, перегрев (WARN). USB-диски не оцениваются: мост не отдаёт S.M.A.R.T. |
| `FreeSpace` | Свободное место на локальных дисках | Системный диск: меньше 10 ГБ (WARN) или 3 ГБ (FAIL); другие диски: меньше 5 % |
| `UnexpectedShutdown` | Аварийные перезагрузки за 30 дней (Kernel-Power 41), отчёты о синих экранах, штатные выключения перед сбоем, список минидампов | Синий экран (FAIL); сбой гибернации, удержание кнопки, потеря питания (WARN) |

## Как устроено

```
Run.cmd               запуск двойным щелчком; находит 64-битную PowerShell 5.1
Invoke-PcDiag.ps1     проверка прав, запуск, вывод, буфер обмена
PcDiag/               модуль, импортируется по пути, без установки
  Core/               реестр проверок, движок, сводка и отчёт
  Checks/             одна проверка — один файл
tests/                Pester
build.ps1             линтер, тесты и smoke-запуск: одинаково локально и в CI
```

Каждая проверка состоит из двух функций:

- `Get-<Id>Data` только собирает данные из системы и возвращает словарь
  простых значений (даты — строками ISO 8601);
- `Test-<Id>` получает эти данные и решает, что с ними не так. Это чистая
  функция: её тестируют на готовых данных, без моков.

Если сбор данных падает, движок ставит проверке статус `ERR` с текстом ошибки
и продолжает остальные. Пустой результат не выдаётся за «всё хорошо».

### Новая проверка

Файл `PcDiag/Checks/Example.ps1`:

```powershell
Register-PcDiagCheck -Id 'Example' -Title 'Пример'

function Get-ExampleData {
    [CmdletBinding()]
    param()
    [ordered]@{ Value = (Get-CimInstance -ClassName Win32_ComputerSystem -ErrorAction Stop).NumberOfProcessors }
}

function Test-Example {
    [CmdletBinding()]
    param([Parameter(Mandatory)] $Data)
    if ($Data.Value -lt 1) { return New-PcDiagVerdict -Status Fail -Summary 'процессоров нет' -Details @('почему это плохо') }
    New-PcDiagVerdict -Status OK -Summary "процессоров: $($Data.Value)"
}
```

И тест `tests/Checks/Example.Tests.ps1`. Контрактные тесты сами проверят,
что у новой проверки есть обе функции.

## Разработка

```powershell
.\build.ps1 -Task Deps          # один раз: Pester 5.7.1 и PSScriptAnalyzer 1.24.0
.\build.ps1                     # линтер и тесты
.\build.ps1 -Task Smoke         # настоящий запуск на этой машине (от администратора)
```

CI в GitHub Actions на `windows-latest` гоняет всё это в Windows PowerShell 5.1 и PowerShell 7.

Правила репозитория:

- `.ps1`, `.psm1`, `.psd1` — UTF-8 с BOM и CRLF (иначе 5.1 портит кириллицу);
  `.cmd` — только ASCII. Это проверяют тесты.
- Код совместим с PowerShell 5.1: это проверяет правило `PSUseCompatibleSyntax`.
- Отчёты с реальных ПК не коммитятся (`reports/` в `.gitignore`). В тестах — только выдуманные данные.
